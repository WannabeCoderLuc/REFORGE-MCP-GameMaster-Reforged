The mission

Bring 3DEN-class authoring into live Game Master.

Nothing in the Arma lineage yet combines 3DEN’s authoring depth, a live network-replicated session, real multi-user collaboration, a documented moddability model, and open source. That gap is the north star.

Preserve vanilla

Keep essential Game Master workflows intact. Additive only — vanilla panels, actions, and content stay.

Documented contracts

Content-only config merges and scripted registration points so creators never touch fragile framework internals.

Multiplayer-first

Client visualisation vs server execution — mutations validate on the server, visual ghosts never enter an RPC.

Twin deliverables

One framework. One research server.

Build the MCP server first, then use it to build the Game Master framework. Both are intended for open-source community handoff.

type-usage edges

“What does this class really inherit?”

Read from the shipped code, not a documentation dump — which had some core editor classes inheriting from their own subclasses.

“Show me one method, not a 79 KB file.”

Symbol-level slicing, and grep that reaches inside the game’s .pak archives where ordinary tools cannot look.

“Who else overrides this file?”

Mods extend Reforger by claiming the same GUID as a vanilla file. An override you didn’t know about is how Game Master mods break each other.

“What components does this prefab actually have?”

Prefabs are partial diffs over their parent, so the file alone tells you little. The inheritance chain is walked and each component’s origin reported.

Found in passing, by tooling built for something else: a stray empty override of the vanilla Game Master mode prefab, sitting inside a working mod in a folder named “trash”. Overrides bind by GUID, not by path — renaming the folder had never unbound it.

What’s new

Build log.

Dated, specific, and honest about what broke. Entries are written when the work lands, not when it is planned — every claim here is traceable to the project’s evidence ledger.

  1. 7 Sep 2026 New

    Workbench runs unattended

    A modal dialog blocks Workbench’s event loop — the same loop that answers the automation bridge — so while one is open, nothing inside the editor can clear it. The server now detects and dismisses those dialogs from outside the process, and can start, close and restart the editor itself.

    Dismissal is reject-only: it can decline a prompt but never accept one, so it cannot confirm a destructive action on your behalf. Save, overwrite and delete prompts are permanently excluded and always left for a human.

  2. 7 Sep 2026 Fixed

    Copying a world silently corrupted it

    Enfusion worlds are binary. The duplicate tool read them as text, so an 867-byte world came back as 950 bytes of replacement characters — unopenable, with no error reported. Copies are now byte-exact.

    The same fix caught a second half of the bug: the sidecar file named a resource class the engine does not have. Class names are now taken from a verified table, and an unknown file type is refused rather than guessed.

  3. 7 Sep 2026 Fixed

    Two tools reported success for nothing

    Running the write tools against a real 173,637-entity world found one that reported a tick — and recorded an undo step — for an operation the engine cannot actually perform, and another that would have coerced a mistyped layer name into layer zero, locking the entire world.

    Both are now impossible: a handler answering “ok” while doing nothing is treated as a failure, and layer ids are validated against the layers that exist. Neither would have been caught by a test fixture.

  4. 7 Sep 2026 Changed

    A timeout no longer means “it didn’t happen”

    A call timed out while the operation it requested had in fact completed — so a real change went unrecorded, and a retry would have applied it twice. Timeouts now report an explicitly unknown outcome and say to verify before retrying.

  5. 7 Sep 2026 New

    The write surface is complete

    Every writer the specification lists now exists: live entity, component, clipboard, layer, prefab, resource, script and localization editing, plus session control — and five scaffolders that consult the indexes before emitting anything, so generated code matches the build you actually have installed.

    One is deliberately absent. Packaging has no engine handler, so rather than fake it through the bridge, it stays unbuilt and visibly listed as such.

  6. 7 Sep 2026 New

    The live bridge came up

    The editor connection that had blocked this project since its second session now answers. The cause of the last hang was ours: the client wrote its request without closing the socket, and the editor reads until end-of-input — indistinguishable, at the network level, from a missing handler.

  7. 6 Sep 2026 New

    Indexes built from your own install

    Symbols, resource GUIDs and a full class hierarchy, all derived locally and stamped with the game build they came from. The shipped documentation index had core editor classes inheriting from their own subclasses; the source-derived one replaced it.

Three of the entries above are defects found by running the tools against a real editor rather than a test fixture. They are listed because a build log that only records wins is not a build log.

T0

Knowledge

Shipping

Derived indexes built from your own installation. No Bohemia content is redistributed — every index is generated locally and stamped with the game build it came from.

  • symbol_lookup a class or enum's real declaration, inheritance chain, members, methods and usedBy
  • signature_check verify a method exists with the signature that actually shipped
  • prefab_resolve a prefab's merged component set, with each component's origin
  • guid_resolve · path_guid resolve a resource GUID either way, reporting how it was determined
  • resource_refs who overrides, inherits from, or references a resource
  • config_merge_preview preview a same-GUID override before it silently replaces vanilla content
  • addon_deps read .gproj manifests and the addon dependency graph
  • api_search · component_search the documentation index — superseded by symbol_lookup, kept as a fallback
  • wiki_search · wiki_read · kb_search indexed BI wiki and a distilled modding knowledge base
  • version_info · capabilities what is indexed, how stale, and what this server may currently do
T1

Filesystem read

Shipping

Confined to configured roots. A path that escapes one is refused with a structured error, never read.

  • source_read one symbol, line range, or match neighbourhood — never a whole 79 KB file
  • source_grep search inside the game's .pak archives, where ordinary tools cannot look
  • logs_read Workbench compile errors and warnings, readable with Workbench closed
  • reindex explicit rebuild against the installed game — never silent
  • diagnose config, roots, manifests, index freshness, bridge reachability
T3

Workbench read

Shipping · opt-in

Live reads over the Workbench NET API. Read-only is enforced by a per-handler action allowlist in the client — necessary because several engine handlers mix reads and writes behind one name.

  • wb_read_props properties as the engine resolves them, inherited values tagged
  • wb_state editor mode, entity and selection counts, current world
  • wb_entity_list · wb_entity_inspect what is in the live world, and what one entity actually is
  • wb_layers_read · wb_prefabs_read layer structure and live prefab ancestry
  • wb_resources_read browse the live resource database, or resolve a GUID as Workbench sees it
  • wb_component_read · wb_localization_read a live entity's components, and the string table
  • wb_script_read · wb_terrain_read · wb_clipboard_read · wb_projects_read
T2 · T4

Write & mutate

Shipping · opt-in

Every writer runs behind a twelve-point safety model: writes confined to declared mod roots, dry run by default with a single-use plan id, an operation journal that records how to reverse each change, explicit confirmation for anything irreversible, and no publish tool at all.

  • file_write write into a writable mod root — returns a real diff first, changes nothing until applied
  • intervention_undo replay recorded inverses, newest first
  • mod_scaffold · game_duplicate a new addon skeleton, or a vanilla resource copied with a fresh GUID — a copy that keeps the original GUID is a merge, not a duplicate
  • script_scaffold subclass a base class using the overridable signatures that shipped in your build, read from the symbol index
  • config_scaffold · layout_scaffold new .conf / .layout resources with minted, collision-checked GUIDs and their .meta
  • wb_entity_create · wb_entity_modify · wb_entity_select spawn, edit and select live entities; undo restores the prior state
  • wb_entity_delete needs explicit confirmation, and is honest that undo will not bring it back
  • wb_component_edit · wb_clipboard_op · wb_layers_edit the live editing surface — a paste is undone by diffing entity names before and after
  • wb_script_edit line edits with a Reload Scripts step attached, because entering play mode does not recompile
  • wb_prefab_save · wb_resources_register · wb_localization_edit write entities out to prefabs, give new files their GUID, edit the string table
  • wb_save · wb_open_resource · wb_play / wb_stop drive the editor session itself; opening a resource is transition-guarded because doing it mid-transition has crashed Workbench
  • wb_menu_action allowlisted menu actions only — an allowlist, never a blocklist
  • wb_dialogs clear the modal dialogs that block the editor's automation bridge — reject-only, so it can decline a prompt but never accept one
  • wb_process start, close and restart the editor; handler code only registers at process start, so this is what makes an unattended add-and-verify loop possible

Reversibility is decided per operation, not claimed per tool. Some undo exactly (a layer lock is a toggle; a script line edit restores the prior text). Some are derived (a paste is undone by diffing the entity list before and after). The rest — saving a prefab, registering a resource, deleting a row — record no inverse and say so, because a fabricated undo that looks like a restore is worse than none.

Architecture

Four pillars of the framework vision.

Research ambition — not a feature-parity promise. Each pillar builds on verified Enfusion editor seams.

  1. 01

    Extend native components

    Precision transform, deep attributes, and advanced logic/waypoints by subclassing SCR_TransformingEditorComponent, SCR_AttributesManagerEditorComponent, and SCR_CommandActionsEditorComponent — not replacing the editor.

  2. 02

    Non-destructive mode override

    A minimal same-GUID override of EditorModeEdit.et injects custom components and UI panels while third parties register through framework-owned lists.

  3. 03

    State serialization pipeline

    Walk editable entities, record transforms and AI order state, reload via server-authoritative SpawnEntityResource — portable scenarios, not fragile SaveGame snapshots.

  4. 04

    Authority separation

    Client UI visualisation vs server execution. Pattern: client request → server re-validate → perform → owner callback. Ghosts and outlines never leave the client.

Why it matters

Three capabilities nobody has done live in Arma.

These are the project’s targets, not shipped features. They are also its highest-risk work: each is rated hard in the feasibility notes and sits at the top of the community’s complaints — which is exactly why they are worth attempting.

Concurrent multi-GM editing

Real permission + concurrency model. Vanilla IsAdmin() is a stub; 3DEN is single-user offline.

Multi-step undo / redo

No prior art in Arma live sessions. Vanilla rewind is a single SaveGame snapshot, not a command stack.

Live triggers & conditions

General “when X, do Y” authored while players are in the world — GM has no free trigger primitive today.

Extension model

Two tiers. No third path.

Creators never override the mode prefab. Contribution goes through framework-owned configs and registrars — the fragile surface stays owned.

Tier A — Content-only

A .conf merge into a framework-owned list. No Enforce scripting. Placeables, presets, display categories.

Tier B — Scripted

An SCR_* subclass plus a registration call. Custom AI orders, panels, trigger conditions, permission policies.

Shipped proof: GMPW Auto Patrol — custom waypoint via same-GUID config merge, live-editable and replicated. That recipe is the template.

Standing goal

Open source. Handed to the community.

Both deliverables are meant to ship with contributor docs, a compatibility policy, and a public docs site — modelled on the already-released Auto Patrol handoff package.
