The mission

Bring 3DEN-class authoring into live Game Master.

Nothing in the Arma lineage yet combines 3DEN’s authoring depth, a live network-replicated session, real multi-user collaboration, a documented moddability model, and open source. That gap is the north star.

Preserve vanilla

Keep essential Game Master workflows intact. Additive only — vanilla panels, actions, and content stay.

Documented contracts

Content-only config merges and scripted registration points so creators never touch fragile framework internals.

Multiplayer-first

Client visualisation vs server execution — mutations validate on the server, visual ghosts never enter an RPC.

Twin deliverables

One framework. One research server.

Build the MCP server first, then use it to build the Game Master framework. Both are intended for open-source community handoff.

Architecture

Four pillars of the framework vision.

Research ambition — not a feature-parity promise. Each pillar builds on verified Enfusion editor seams.

  1. 01

    Extend native components

    Precision transform, deep attributes, and advanced logic/waypoints by subclassing SCR_TransformingEditorComponent, SCR_AttributesManagerEditorComponent, and SCR_CommandActionsEditorComponent — not replacing the editor.

  2. 02

    Non-destructive mode override

    A minimal same-GUID override of EditorModeEdit.et injects custom components and UI panels while third parties register through framework-owned lists.

  3. 03

    State serialization pipeline

    Walk editable entities, record transforms and AI order state, reload via server-authoritative SpawnEntityResource — portable scenarios, not fragile SaveGame snapshots.

  4. 04

    Authority separation

    Client UI visualisation vs server execution. Pattern: client request → server re-validate → perform → owner callback. Ghosts and outlines never leave the client.

Why it matters

Three capabilities everyone said couldn’t be done live.

Ranked community pain points and the hard feasibility rows share the same inventions.

Concurrent multi-GM editing

Real permission + concurrency model. Vanilla IsAdmin() is a stub; 3DEN is single-user offline.

Multi-step undo / redo

No prior art in Arma live sessions. Vanilla rewind is a single SaveGame snapshot, not a command stack.

Live triggers & conditions

General “when X, do Y” authored while players are in the world — GM has no free trigger primitive today.

Extension model

Two tiers. No third path.

Creators never override the mode prefab. Contribution goes through framework-owned configs and registrars — the fragile surface stays owned.

Tier A — Content-only

A .conf merge into a framework-owned list. No Enforce scripting. Placeables, presets, display categories.

Tier B — Scripted

An SCR_* subclass plus a registration call. Custom AI orders, panels, trigger conditions, permission policies.

Shipped proof: GMPW Auto Patrol — custom waypoint via same-GUID config merge, live-editable and replicated. That recipe is the template.

Standing goal

Open source. Handed to the community.

Both deliverables are meant to ship with contributor docs, a compatibility policy, and a public docs site — modelled on the already-released Auto Patrol handoff package.
